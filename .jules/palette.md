## 2024-05-24 - Form accessibility enhancements
**Learning:** Adding correct explicit `for` attributes to decoupled `<label>` elements mapped to `<input>` IDs significantly improves screen reader navigation and mouse hit targets in ezManage's Auth, Setup, and Tracker forms. Also learned that adding explicit `for` attributes to labels that already wrap their target input is redundant. Adding `aria-live` to rapidly updating timers should be avoided.
**Action:** Next time, only apply `for` mapping to non-wrapping labels. When linking descriptive text to buttons, use `aria-describedby` instead of `aria-labelledby` if the intention is to append description rather than overriding the button's visible text. Avoid using `aria-live` for continuously polling elements like stopwatches, as it overwhelms the user.

## 2024-05-24 - Accordion semantics and keyboard support
**Learning:** In the ezManage app, the interactive collapsible headers in `index.html` were implemented using `<h3>` elements and a click handler. However, they lacked proper keyboard support (`Enter` and `Space`), semantic button roles, and state communication (`aria-expanded`). Furthermore, applying `role="button"` directly to the heading overwrites the heading role itself, breaking screen reader heading navigation. The proper solution is to wrap the content of the `<h3>` in a semantic `<button>` tag.
**Action:** Next time, ensure all custom interactive elements, such as collapsibles or accordions, use actual semantic `<button>` elements wrapped inside headings if structural hierarchy needs to be preserved, manage `aria-expanded` state natively, and apply `focus-visible` styles rather than relying on default outline suppression.
